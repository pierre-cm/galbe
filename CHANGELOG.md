## Unreleased

### Breaking changes
- **`galbe/middlewares` re-cut around one auth contract.** `jwt({ publicKey })` is now `jwt({ key })` — one name for an HMAC secret and for a public key alike — and all four auth middlewares take **`optional: true`** to let a request carrying no credential through unauthenticated. An `errorHandler` returning nothing no longer means "let this request through": it falls back to the default `401` (`429` for `rateLimit`), so a handler that only logs can no longer disable authentication by accident. Under `optional` a credential that is present and refused is still rejected — being anonymous is not the same as presenting a bad token.
- **A configured credential is never copied onto `ctx.state`.** `bearer({ token })`, `apiKey({ key })` and `basicAuth({ verify })` returning `true` store `true` under the state key rather than the token or key itself: the presence of the key is what says "authenticated", which is what keeps optional auth readable. `basicAuth` authenticates a username from its `users` map, so that name remains the identity it stores, and `basicAuth({ users: {} })` is now a registration-time `SyntaxError` instead of a middleware that rejects every caller.
- **`logger` and `timing` report every routed request**, the ones the hook chain never sees included — a `400` from validation, a `401` from an auth middleware, a `500`. Both start their clock in `beforeParse` and write in `afterHandle`, so `logger`'s `duration` and the `Server-Timing` entry now cover parsing and validation rather than the hook chain alone, and `logger`'s entry carries the error a failing request ended on. `logger`'s `skip` still sees the finished request. Only a request that matched no route stays out of their reach, as it always did.
- **`requestId` checks the id its `generate` returns.** An id that could not travel in a response header or survive a log line — anything outside 128 characters of `[A-Za-z0-9_.:-]` — now fails the request with a `500` naming `generate()`, instead of surfacing as a `TypeError` from the `Headers` constructor.
- **OpenAPI security is declared, never inferred**: the serializer no longer sniffs a `/^Bearer /` pattern on an `authorization` header to synthesize a `bearerAuth` scheme and requirement. An operation documents as authenticated only where a scheme is named — a route's `@security`, its route file's header, or the `security` of a middleware def covering it — so a hand-declared `Authorization` header now documents as an ordinary header parameter. Apps relying on the inference (notably the `galbe-jwt` plugin, whose whole job was patching that pattern onto route schemas) should register [`jwt`](./docs/reference/middlewares.md#jwt) as middleware, or add `@security bearerAuth` where the scheme is enforced. In exchange, a scheme now suppresses the parameter for the credential it names wherever it was declared — app config included, not only middleware defs.
- **Request schemas gained a `cookies` slot, and `ctx.cookies` is typed from it**: previously always `Record<string, string>`, it is now `Static<>` of the declared schema (undeclared cookies remain raw strings). `RequestSchema`, `Route`, `Endpoint` and the route builders gained a trailing `C extends STCookies` generic — `Route<…>` users passing `SP`/`SR` positionally must shift them by one.
- **A bare `$T.null()` response means "no body" at every status**, not only `204`/`304`/`1xx`. A genuine JSON `null` body stays expressible through the content-map form `{ 'application/json': $T.null() }`.
- **Directory groups are on by default**: a route file's directory relative to its glob's static base is now its path prefix (`src/api/users.route.ts` → `/api/...`). Files at the glob base are unaffected; files in subdirectories change URLs. Opt out with `routes: { pattern, dirPrefix: false }`, or per file with a `/** @prefix / */` header.
- **OpenAPI specs no longer bake `basePath` into `paths`**: it is surfaced through `servers` instead (`[{ url: basePath }]` when no explicit `config.openapi.servers` is set; explicit config wins).
- **`GalbeProxy` removed**: route files now receive a plain `Galbe` (or a prefix-bound group registrar) instead of the async proxy, and registrations are synchronous. Files that treated `galbe.get(...)` as a `Promise<Route>` now get the `Route` directly; plain `await`s on those calls keep working.

### Features
- **Middleware `afterHandle` slot**: a `MiddlewareDef`'s `afterHandle` hooks now run, on every route the definition matches, once the response is parsed — **whatever the request ended on**, an error response built by the Error Handler included. They are a transform over the `Response`, not an onion (`(response, ctx, error) => Response | void`, `error` being what the request ended on), they run once per request and ahead of the plugins' `afterHandle`, and they are the only middleware slot that sees a request rejected before the hook chain: a `400` from validation or a `401` from a `beforeParse` middleware never reaches the chain, but it does produce a `Response`. Their position in the lifecycle is `handler → response parsing → middleware afterHandle → plugins.afterHandle`. This is what lets `logger` and `timing` cover the whole request rather than the chain.
- **Typed cookies**: a `cookies` property on the request schema parses, coerces and validates each declared cookie like a query parameter, reports failures under a `cookies` key, and emits `in: cookie` parameters in the OpenAPI spec.
- **Response status ranges**: `'1XX'`…`'5XX'` are response-map keys alongside exact statuses and `default`. One resolution rule — exact status, then the range containing it, then `default` — governs response validation, the content type inferred for a string response, the emitted spec and the generated client.
- **New schema options**: `multipleOf` and `format` on numbers (the `int32`/`uint32`/`int64`/`uint64` formats also constrain the range at runtime), `additionalProperties` on objects with the `$T.record(value)` sugar for free-form maps, `readOnly`/`writeOnly` (documentation only), `encoding` on `$T.multipartForm`, `responseLinks` on responses, and `split` on arrays.
- **Object query parameters**: `$T.object` is a legal query schema, read from bracketed keys (`?filter[lat]=1&filter[lon]=2`, OpenAPI's `deepObject`) or from a JSON-encoded value. An array's `split` option sets the delimiter that splits a single value — `'|'` and `' '` being `pipeDelimited` and `spaceDelimited` — and `split: false` keeps a delimiter-bearing value as one item.
- **`@summary` and `@description` annotations** override the JSDoc head split. A bare `@summary` declares an explicitly empty one, which is the only way to express a description with no summary.
- **Route-file header annotations apply to the file's routes**: `@tags` and `@security` above a route file's default export now reach every route it declares, as a middleware file's header already did. Precedence runs from the nearest scope outwards — route, then its file's header, then the middleware covering it.
- **Document-level OpenAPI config**: `openapi.tags`, `openapi.security`, `openapi.externalDocs` and `openapi.securitySchemes` in `GalbeConfig`.
- **`galbe generate code` reports what it cannot carry**: constructs the schema model cannot express (`not`, `allowEmptyValue`, unimplemented parameter styles, methods with no route builder, unrecognised response keys) are printed instead of dropped silently.
- `galbe.onRouteAdded(cb)`: public registration event, firing synchronously for every route added with its final path; returns an unsubscribe function.
- Middleware files: `GalbeConfig.middleware` glob (default `src/**/*.middleware.{js,ts}`), scoped to their directory subtree, with deterministic ordering. A file default-exports a `MiddlewareDef` (with an optional `export const scope` narrowing) or a registration function receiving a directory-scoped registrar, which may register several middlewares.
- Middleware schema fragments: `galbe.middleware(pattern?, def)`, `group.middleware`, `galbe.group(prefix, def, cb)` and middleware files accept a `MiddlewareDef` (`{ hooks, schema, security, securitySchemes }`). The `schema` fragment (`headers`/`query`/`params`) is merged into every matched route at registration — route-declared keys win — so validation, the OpenAPI spec, `generate client` and `generate cli` all pick up a subtree-wide request contract.
- **Middleware-declared OpenAPI security**: a definition's `security` now reaches the spec, so a middleware registered in code documents itself exactly like the same middleware in a `*.middleware.ts` file with a `@security` header — names, space-separated scopes (`'oauth2 read write'`), lists of alternatives and the `'none'` public escape all behave as the annotation does. A def may also define the schemes it names through `securitySchemes` (same shape as `config.openapi.securitySchemes`, which wins on conflict), which is what makes an `apiKey` or `basic` middleware expressible at all; the credential such a scheme names (`http` ⇒ `Authorization`, `apiKey` ⇒ its `name`/`in`) is then documented as auth instead of also appearing as a plain parameter. Precedence: the route's `@security`, then its route file's header, then the nearest middleware scope — a file's header ahead of the def it annotates — then the legacy `/^Bearer /` header inference, which stays for hand-declared route schemas.
- **Middleware `beforeParse` slot**: a definition's `beforeParse` hooks run on every matched route after routing and before the body is read or the request validated, so an auth or rate-limit rejection answers **401 before 400** instead of after a full parse. The context carries `request`, `route`, `state`, `set`, `cookies` and `remoteAddress` — no `body`, `params` or parsed `query`, which do not exist yet. Hooks take no `next()`: they run in registration order and preempt the request by returning a `Response`, like a plugin's `onRoute`. Routes with no matching `beforeParse` skip the stage entirely.
- **Built-in middlewares under `galbe/middlewares`** (also importable one by one, `galbe/middlewares/jwt`), starting with **`jwt`**: verify-only JWT authentication on `crypto.subtle` — no new dependency — covering the `HS`, `RS` and `ES` families, with PEM, JWK, raw-secret and `CryptoKey` keys. It runs in the `beforeParse` slot, so an unauthenticated request is answered 401 before its body is read, and the key decides which algorithms are acceptable, never the token's `alg` header. Reads the token from `Authorization: Bearer` or a cookie, checks `exp`/`nbf`/`iss`/`aud`/`sub` with an optional clock tolerance, exposes the payload on `ctx.state.jwtPayload`, and contributes both the `authorization` header fragment and the OpenAPI security scheme enforcing it. `signJwt(payload, key, options)` issues the matching tokens — a separate export, so a private key never sits on the verification path.
- **`bearer`, `apiKey` and `basicAuth`**: the other three credential checks, on the same contract as `jwt` — `beforeParse` (401 before the body is read), an `AuthError` with a `missing`/`malformed`/`invalid` code handed to `errorHandler` (return a `Response` to answer, nothing to fall back to the default 401), optional authentication declared with `optional: true`, the credential declared as a schema fragment and the OpenAPI scheme that owns it (`securityScheme` renames it, `false` opts out). Configured secrets are compared in constant time over SHA-256 digests, and `basicAuth` matches the whole `user:password` pair so an unknown user is indistinguishable from a wrong password. `bearer` and `apiKey` take either a constant credential or a `verify` lookup whose return value becomes the identity on `ctx.state` (a configured constant stores `true`, never the credential); `apiKey` reads a header, a query parameter or a cookie; `basicAuth` decodes UTF-8 credentials and answers with a `realm` challenge.
- **Observability: `requestId`, `logger` and `timing`**: `requestId` runs in the `beforeParse` slot so the id exists before anything can reject the request — a `400` from validation or a `401` from an auth middleware registered after it carries the header too — reusing a well-formed inbound id (at most 128 characters of `[A-Za-z0-9_.:-]`, anything else replaced rather than rejected) unless `trustHeader: false`, and putting it on `ctx.state` under a configurable key. `logger` wraps the hook chain and reports the status a request *ended* on, an error included, with method, query-less path and duration, either as a console line or through a `log` callback; both it and `timing` take a `skip` that sees the finished request. `timing` appends to `Server-Timing` rather than overwriting it, so a measurement a route added survives alongside it. All three live under [`galbe/middlewares`](./docs/reference/middlewares.md#observability), each also importable on its own path.
- `middleware(def)` helper (identity at runtime, like `config()`): a definition's `schema` fragment types its own hooks, and `galbe.group(prefix, def, cb)` types every route registered through the group registrar with it — route-declared keys win, nested group definitions stack.
- `@prefix` route-file header annotation declaring an explicit path prefix.
- `galbe generate code` emits the directory-convention layout with relative paths, so generated trees round-trip through the analyzer; route identity in merges is prefix-aware.

### Fixes
- **Route discovery is deterministic**: route files are now ordered the way middleware files already were — directory depth (shallowest first), then path — instead of being registered in the order the filesystem happens to return them. A directory scan's order differs between machines, so the `paths` order of an emitted spec, the route table `galbe dev`/`galbe build` prints, and the parameter name a shared router node keeps could all change between two checkouts of the same code — a developer's machine and CI, for instance — with no source change to explain it.
- **OpenAPI round-trip**: a shared component schema is no longer corrupted by response metadata; `components.requestBodies` references survive instead of becoming garbage media types; every `components.responses` entry keeps its identity, its description and (new) its response headers; named example `$ref`s no longer dangle; exclusive bounds use the OpenAPI 3.0 boolean form; parameter descriptions are no longer duplicated onto their schema; request-body descriptions are carried rather than inferred from the body schema.
- The route listing printed by `galbe dev`/`galbe build` shows a route's description again: a single-paragraph JSDoc head (the common `/** Greeting endpoint */` case) was analyzed correctly but dropped from the log, which only printed heads carrying a blank line. Log and OpenAPI spec now share one summary/description rule.
- The Automatic Route Analyzer no longer scans `node_modules` and `.git`: an app-wide pattern such as `routes: '**/*.route.ts'` used to import route and middleware files shipped by dependencies, and a dependency directory that isn't a valid route segment aborted boot (`galbe dev` and `galbe build` alike). A pattern that names one of those directories explicitly still opts back in.
- `galbe dev --watch` no longer reloads on `.git` writes (a `git checkout` or `git commit` used to respawn the app), and `--watchignore` now *adds* to the built-in ignores (`node_modules`, `.git`, `.galbe`) instead of replacing them.
- `galbe build` no longer swallows boot errors: a single thrown error (invalid directory name, failed import) was reported as `TypeError: {} is not iterable` instead of itself.
- Route-file metadata (tags, summaries, `@galbe-hide`, ...) is no longer silently dropped when `basePath` is set: meta keys are rewritten to final paths relative to `basePath` and all consumers look up accordingly.
- `galbe build` now also copies static assets registered in the main entry file (previously only route-file registrations were copied).
