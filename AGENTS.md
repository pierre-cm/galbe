# Galbe

Fast, lightweight web framework for **Bun** (TypeScript). This repository _is_ the `galbe` npm package: the framework source, the Galbe CLI, the generated-code tooling and the test suite. This file is contributor-facing and **gitignored** (`.gitignore` lists `AGENTS.md`, `REVIEW.md` and `tasks/`), so edits to it are never committed and it is never published: app authors get `docs/` instead.

If you read only two sections, read **Conventions & invariants** (rules that break silently when violated) and **Known gaps** (verified defects with no test coverage).

## Commands

- `bun test` — Bun test runner over `test/*.test.ts` (31 files). Run it from the repo root: tests reference `test/resources/**` by relative path.
- `bun run typecheck` — `tsc --noEmit` over `tsconfig.json` (src only, `noUncheckedIndexedAccess: true`) then `tsconfig.test.json` (src + test + bin, that flag off). Type-level guardrails (`test/schemaTyping.test.ts`, `test/types.test.ts`, `test/json.test.ts`) fail _only_ here.
- `bun run format` / `bun run format:check` — prettier, a pinned devDependency. CI runs `format:check`.
- `bun run release [--ci] [--scope patch|minor|major]` — `scripts/release.ts`: gates on branch `main` + a clean tree (skipped under `--ci`), classifies commits since the last tag, bumps, prepends a `## <version> — <date>` section _above_ `## Unreleased`, rewrites `package.json`, then commits, tags, pushes to a **hardcoded SSH remote** (not `origin`) and runs `gh release create`. `npm publish --provenance` happens in CI, not here. `scripts/` is in no tsconfig project, so it is not typechecked.

CI: `.github/workflows/build_test.yml` (every push and PR) runs `bun install` → `bun run format:check` → `bun run typecheck` → `bun test`. `.github/workflows/release.yml` is `workflow_dispatch`-only (required `scope` input) and has **no format/test gate** before publishing. Pushing `docs/**` to `main` triggers a redeploy of the website repo (`.github/workflows/deploy_website.yml`).

**Environment gotchas.** The two OpenAPI tests and `generateMerge.test.ts` spawn the CLI, which writes into the OS temp dir and runs `bunx prettier --write` (network on a cold bun cache). In a sandbox that denies tempdir writes or network they fail with `bun is unable to write files to tempdir: EACCES` — an environmental failure, not a regression. Several test files bind fixed ports (7357–7430, 47211, 47220), so a busy port fails that file.

## Package surface

No build step: the package ships raw TypeScript (`main`/`types` → `./src/index.ts`), and it is **Bun-only** by design (`engines.bun >= 1.2.21`; every `exports` subpath self-references the `.ts` file under both the `types` and `default` conditions). Node/Deno support is a non-goal. Subpaths are public API: `.`, `galbe/schema`, `galbe/middlewares`, `galbe/middlewares/*`, `galbe/extras`, `galbe/utils`. `files` is `["bin/", "src/"]` — `docs/` and this file are not published.

Dependency policy: keep runtime `dependencies` lean, and keep all of them out of the `galbe` runtime entry graph (`src/index.ts` → `server.ts`/`parser.ts`/`router.ts`/`validator*.ts`/`schema.ts`/`util.ts`/`cookies.ts`/`types.ts`). Note that `src/index.ts` and `src/util.ts` import `./routes` with `import type`, which is what keeps the analyzer out of that graph.

- `acorn`, `acorn-walk` and `@swc/wasm` are loaded only by `src/routes.ts` (and `@swc/wasm` also by `bin/commands/generate/{client.ts,code/openapi.parser.ts}`). Keep `@swc/wasm` — the portable WASM build. Do not reintroduce `@swc/core` and its per-platform native binaries.
- `commander` is loaded only by `bin/`.
- `openapi-types` is imported as `import type` throughout `src/` (erased at runtime; used by `types.ts`, `extras/spec/openapi.serializer.ts`, `middlewares/_auth.ts`) and as types by the generator in `bin/`.
- `typescript` is a **peer** dependency (`^5`), needed by `bun run typecheck` and, at runtime, by `galbe generate code` (`bin/commands/generate/code/route-merge.ts` uses the compiler API to rewrite route files in place).
- `cac` is not a dependency of this package: it is the runtime dependency of the _generated_ CLI.

## Layout

- `src/` — framework core:
  - `index.ts` — `Galbe` class (route builders `get/post/put/patch/delete/options/head`, `static`, `use`, `middleware`, `group`, `onRouteAdded`, `listen`/`stop`), the `$T` schema builder instance, the `config()` and `middleware()` identity helpers, `GalbeGroup`, and the boot-time chain composition (`composeHooks`, `composePreParse`, `composePost`).
  - `server.ts` — `Bun.serve` wiring and the whole request lifecycle. Owns `port`, `fetch` and `error`; `config.server` is passed through otherwise, and it receives the request context, cookie queue, plugin callbacks and the boot-compiled client-address resolver.
  - `router.ts` — trie router (static > param > wildcard) with an exact-path cache and an optional bounded LRU; `remove()` unregisters a route (identity-checked) for `@galbe-ignore`.
  - `parser.ts` — body parsers (json/text/byteArray/urlForm/multipart, each with a streaming variant), `parseEntry` (headers/query/params/cookies), `requestPathParser`, `responseParser` (string/object/Uint8Array/Response/SSE async iterators), plus the body-size enforcement helpers.
  - `schema.ts` — `$T` schema types (`Kind`/`Optional`/`Stream` symbols, `Options` per kind), `Static<>` inference, and `schemaToTypeStr` (used by the client/CLI generators).
  - `validator.ts` — interpreter: `validate` (request) and `validateResponse`. Throws plain strings on invalid input; error messages are part of the contract.
  - `validator.compile.ts` — AOT compiler: `compile()` builds a specialized validator per schema, cached on the schema object under the `Compiled` symbol; `compileRoute()` runs at route registration; `runCompiled()` is the hot-path entry with interpreter fallback. Compiled and interpreted validators must accept/reject exactly the same inputs and throw the same messages.
  - `cookies.ts` — `readCookies`, `parseCookie`, `stringifyCookie` (percent-encoding in, 400 on unencodable input, control-character rejection out), `CookieOptions`.
  - `util.ts` — `HttpStatus`, `walkRoutes`/`walkMetaRoutes`, `logRoute`, `joinPath`, `splitHead`/`routeHead` (the single summary/description rule), `responseRangeOf`/`responseEntryFor` (the single response-resolution rule), `softMerge`, `inferBodyType`, `isIterator`, middleware pattern parsing/matching and `mergeMiddlewareSchema`, and `clientAddressResolver` (the `trustProxy` walk behind `ctx.clientAddress`).
  - `types.ts` — the public type surface (`GalbeConfig`, `RequestSchema`, `Context`, `Endpoint`, `Route`, `GalbePlugin`, `MiddlewareDef`, `PreParseHook`/`ResponseHook`, client/CLI types), `RequestError` and the `mkErr` HTTP error classes.
  - `routes.ts` — Automatic Route Analyzer (ARA): globs route and middleware files, extracts JSDoc metadata via acorn + `@swc/wasm` `transformSync` (`Bun.Transpiler` is not an option — it strips comments), computes directory/`@prefix` scopes, and imports each file with a registrar bound to its prefix. Consumers: `bin/`, never the runtime.
  - `middlewares.ts` + `middlewares/*` — the built-in middleware set, see below.
  - `extras.ts` → `extras/spec/openapi.serializer.ts` — `OpenAPISerializer`, the OpenAPI 3 generator (`galbe/extras`).
- `bin/` — the `galbe` CLI, all commander-based: `cli.ts` (wiring), `commands/dev.ts`, `commands/build.ts`, `commands/info.ts`, `commands/generate/{spec,client,model,code,cli}`, `commands/generate/code/{openapi.parser.ts,route-merge.ts}`, `commands/generate/cli/targets/cac.ts`, `util.ts` (shared boot/reload/watch helpers + `instanciateRoutes`, which prints the route table), `res/client.runtime.ts`.
- `test/` — Bun tests, one file per area, plus helpers (`test.utils.ts`, `cli.utils.ts`, `openapi.diff.ts`), fixtures (`test/resources/**`) and snapshots (`test/__snapshots__/**`).
- `docs/` — the user documentation; `tasks/` — the local task tracker (see below).

## CLI (`bin/`)

`dev <index>` (watch + reload), `build <index>` (bundle, `-C/--compile`), `generate {spec,client,code,model,cli}`, `info`. Flags and prose live in `docs/reference/cli.md`; the agent-relevant invariants are:

- Every user path resolves against `CWD = process.cwd()`, captured at import time in `bin/util.ts` — not against the index file's directory. `bun run typecheck` covers `bin/`; `scripts/` is in no tsconfig project.
- Error convention: `console.log('error: …')` + `process.exit(1)`; action handlers do not throw out to commander. `generate spec` and `generate code` are the two that end without an explicit exit.
- `dev`: `WATCH_IGNORE` (node_modules, `.git`, legacy `.galbe`) is always applied inside `watchDir`, and `--watchignore` _adds_ to it. Reload picks a strategy at runtime (`resolveReloadStrategy`): `Loader.registry.clear()` where available, else respawning a child process that does **not** inherit `-w/-wi/-nc`. A failed reload only logs and leaves the dev server stopped until the next save. `BUN_ENV` is forced to `development` when unset, which is what prints the "🚀 Server running at …" line.
- `build`: writes a synthetic entry under the OS temp dir, replays `galbe.middleware(scope, def)` and each route/middleware file's registration, sets `BUN_ENV=production`/`GALBE_BUILD`, and copies each `staticTargets` entry to `<out>/static-<buildId>/<target>` (which is where `static()` looks in production). galbe's own modules are imported from the CLI's install dir on purpose, so pnpm/hoisted/global installs work — do not "simplify" that to `<app>/node_modules/galbe`.
- `generate code` merges into existing sources with the TypeScript compiler API: a route is only recognized as a top-level `g.<method>("path", Ident, …)` statement in the default-exported body, ids are `"METHOD <full path>"` (prefix-aware), and **handler bodies are preserved verbatim** — user implementations survive regeneration. Unresolved routes that exist in code but not in the spec abort with exit 1 unless `--remove-stale`/`--ignore-route`, and constructs it cannot express are printed as warnings. It ends by running `bunx prettier --write` (the app's prettier, network on a cold cache).
- `generate spec` writes YAML/JSON itself (no prettier); a `--base` spec is `softMerge`d **over** the generated one, so it wins.
- `generate client` emits source text (no prettier) with `bin/res/client.runtime.ts` inlined as a string; `-t` is inferred from the _index argument's_ extension, not from `--out`.
- `generate cli` has two modes: `standalone` builds a compiled binary, which means writing a temp project with `cac` as a dependency and running `bun install` there (network), while `module` just writes a file.
- `silentExec` (`bin/util.ts`) mutes `console` and `process.stdout/stderr.write` with no `try/finally`; keep callers' own error handling if you touch it.

## Request lifecycle

Registration happens at boot and composes everything it can: `Galbe.add` compiles the route's validators (`compileRoute`), adds it to the router, matches the middlewares registered so far, merges their schema fragments into the route schema, and composes the three route functions (`composed`, `composedPre`, `composedPost`). A later `galbe.middleware()` call recomposes every already-registered matching route, so middleware may be declared after the routes it targets and costs nothing per request.

Per request (`server.ts`), in order:

1. reject methods outside `GET/POST/PUT/PATCH/DELETE/OPTIONS/HEAD` with a bare `501`.
2. `plugins.onFetch` — each may short-circuit by returning a `Response`.
3. route lookup (`router.find`); a miss is `NotFoundError`, a method mismatch is `MethodNotAllowedError` with an `Allow` header, and `HEAD` falls back to the `get` route (the body is stripped at the end, RFC 9110 §9.3.3).
4. `plugins.onRoute`.
5. `route.composedPre` — matched middleware `beforeParse` hooks: sequential, no `next()`, short-circuit by returning a `Response`. This is the auth/rate-limit slot: it answers before a byte of body is read, so a `401` precedes any validation `400`.
6. body parsing: a `content-length` over `schema.bodyLimit ?? config.bodyLimit` is rejected up front, and the limit is enforced again while reading (chunked clients with no or forged `content-length`).
7. request validation (`config.requestValidator.enabled`, default on): headers, query, params and cookies are parsed and validated independently; every failure is collected and reported as a single `400` whose payload merges all of them.
8. `plugins.beforeHandle`.
9. `route.composed` — matched middleware hooks, then route hooks, then the handler, as one onion chain. A hook that returns a value short-circuits and becomes the response; a hook that neither calls `next()` nor returns triggers an implicit `next()`; a second `next()` logs `Hook already called - ignored`.
10. `responseParser` builds the `Response` (adding queued cookies and `ctx.set.headers`), then response validation runs when `config.responseValidator.enabled` and a schema exists and the handler did not return a raw `Response`.
11. `route.composedPost` — matched middleware `afterHandle` hooks: a transform (`(response, ctx, error) => Response | void`), not an onion, one pass per request.
12. `plugins.afterHandle`, then the `HEAD` body strip.

Errors unwind to one place in the same `fetch`: `context.set.status` is set from the error, the app error handlers (`onError`) get first refusal, and `RequestError` keeps its `status`, `payload` and `headers` (cookies and `set.headers` are merged with append semantics). A `composedPost` that has not run yet **does** run on the error response — that is how `logger` and `timing` report a `400` or a `401` — and one that throws must not cost the request its answer. Anything that is not a `RequestError` is logged and becomes a 500.

## Built-in middlewares (`galbe/middlewares`)

Every one is a plain `MiddlewareDef` value, so it is accepted anywhere a hook is; each is also importable on its own path (`galbe/middlewares/jwt`). All of them fill `beforeParse` and none of them uses the `hooks` slot; `logger` and `timing` additionally fill `afterHandle`. A def whose slots, `schema`, `security` and `securitySchemes` are all empty is dropped at registration.

- `middlewares/_auth.ts` — internal, shared by the four auth middlewares; only `AuthError` (code `missing` / `malformed` / `invalid`) is public. It holds the rejection contract in one place: `authHook` maps an `AuthError` to the `errorHandler` (whose returning nothing falls back to the default `401` — returning nothing is never a way to authenticate), while anything that is not an `AuthError` is rethrown. `AuthError` is **not** a `RequestError`, so one raised outside `authHook` is a plain 500. It also holds `secretMatcher` (SHA-256 both sides, constant-time, every candidate compared with no short-circuit so neither the configured secret's length nor the position of the first differing byte is observable), `readCredential` (query from the raw URL, cookies via `Object.hasOwn`, header prefix matched case-insensitively — so a wrong scheme reports `missing`, not `malformed`), `checkRealm` (rejects quotes/backslashes/control characters at factory time) and `securityMetadata` (name collisions get a numeric suffix).
- `jwt` — verify-only JWT on `crypto.subtle`, no dependency: HS256/384/512, RS256/384/512, ES256/384/512 (`none` is absent and nothing outside the list is ever accepted; the **key** decides the acceptable set — the token's `alg` header never does, which is what closes RS256→HS256 confusion). Keys may be an HMAC secret, PEM SPKI/pkcs8, JWK or `CryptoKey`; sources are `Authorization: Bearer` and/or `cookie:<name>`; checks `exp`/`nbf`/`iss`/`aud`/`sub` with a clock tolerance; stores the payload on `ctx.state.jwtPayload`. The factory is synchronous, so a bad key surfaces as a **500 on the first request**, not at registration. The `authorization` fragment and the `bearerAuth` scheme are contributed only when the bearer source is active; a cookie-only instance answers a bare 401. `signJwt` is a separate export so a private key never sits on the verification path.
- `bearer`, `apiKey`, `basicAuth` — same contract in `beforeParse` (a `401` before the body is read) with the scheme's challenge header (`apiKey` sends none). All four take `optional: true`, which forgives _absence_ only: a credential that is present and refused is still rejected. `bearer` and `apiKey` take a constant credential or a `verify` lookup whose return value becomes the identity on `ctx.state` — a configured constant stores `true`, never the secret; `bearer`/`apiKey` throw a `SyntaxError` at construction when neither is given. `apiKey` reads a header, query parameter or cookie, and contributes a schema fragment only for the header and query locations. `basicAuth` decodes UTF-8 credentials, matches the whole `user:password` pair (so an unknown user is indistinguishable from a wrong password) and requires a non-empty `users` map or a `verify`.
- `rateLimit` — `beforeParse` token bucket: `limit` tokens refilled over `window` seconds, a 429 with `retry-after` (lowercase) when empty, plus `ratelimit-limit`/`ratelimit-remaining` (post-spend)/`ratelimit-reset` written _before_ the throw so a 429 carries them too. `key` defaults to `ctx.clientAddress` (set `trustProxy`, or every client behind your proxy shares a bucket; a falsy return exempts the request). The store is a per-instance closure `Map`, hard-bounded by `maxKeys` (default 10 000) with a bounded 16-entry eviction sweep — keep both properties when touching `consume`/`evict`. It is per-process: N replicas allow N×`limit`.
- `requestId` — `beforeParse`, so the id exists before anything can reject the request: reuses an inbound id matching `/^[\w.:-]{1,128}$/` unless `trustHeader: false` (a malformed inbound id is replaced, not rejected), generates one otherwise (a `generate()` returning anything else is a 500 naming `generate()`), stores it under `ctx.state.requestId` and echoes it in the response header.
- `logger` — fills `beforeParse` (start the clock) and `afterHandle` (report the finished request), which is what lets it report a status the hook chain never produced. The clock lives in a `WeakMap<ctx, number>`, deliberately not on `ctx.state`; the entry's `path` carries no query string (a query can hold a token); `skip` runs once the request is done; the default console line prints no error detail, so a custom `log` is where stacks go. It reads `ctx.state.requestId`, so register `requestId` first.
- `timing` — same two slots; appends to the (`server-timing`) header rather than overwriting it, so a measurement a route added survives. `name` and `header` are sanitized, `precision` is validated, and a `description` containing quotes or control characters is a `SyntaxError`.
- Neither `logger` nor `timing` can see a request that matched no route (a 404, a preflight, or one a plugin answered in `onFetch`): middleware only ever runs for a matched route. Unrouted coverage belongs in a plugin.

## Conventions & invariants

- **Untrusted-key maps must be null-prototype** (`Object.create(null)`) or guarded with `Object.hasOwn`/`getProp` — request-controlled keys (headers, query, form fields, cookies, route segments) must never hit `Object.prototype` members. Live examples: `newChildren()` in `router.ts`, the lazy `context.headers` getter and the query map in `server.ts`, `getProp` in `parser.ts`, cookie/credential lookups in `middlewares/_auth.ts`. Keep this discipline when touching `router.ts`, `server.ts`, `parser.ts`.
- The router ignores trailing slashes when matching (`/a` === `/a/`); `/` itself is special-cased. Precedence is static > param > wildcard, with backtracking (a null sentinel, not exceptions). Wildcard `*` matches exactly one segment plus the parent path when terminal (`/a/*` matches `/a`), and swallows the remaining segments once the deeper walk finds nothing. Params sharing a trie node keep the **first registered** name, which `router.warn` reports.
- The cache is a bounded LRU by `cacheLimit` (default 1024), including cached misses (DoS hardening). Fully literal paths are cached at registration regardless of `cacheEnabled`; `cacheEnabled` (default **off**) additionally caches dynamic lookups and misses. `remove()` purges the entries pointing at the removed route. `router.warn` is the injectable channel for registration-conflict warnings (its default is silenced when `BUN_ENV === 'production'`).
- Middleware patterns (`parseMiddlewarePattern`) are `/`-separated literals or `*`; `:param` is a routing concept and throws a `SyntaxError` there. `*` matches any single segment (params and wildcards included) and a **trailing** `*` matches the whole subtree plus the prefix itself. `/*` and `*` are the same, canonical global pattern. Patterns match **registered route paths**, so `/user/me` does not attach to a route declared `/user/:id`. Group prefixes are converted with `patternFromPath`, so a group on a `:param` prefix scopes its middleware as `*`.
- `mergeMiddlewareSchema` always re-merges from the _declared_ schema (stashed under the `Galbe.Route.DeclaredSchema` symbol), never from a previous merge result — otherwise the outcome would depend on the order of `middleware()` calls. It is copy-on-merge: a `RequestSchema` object shared by several routes is never mutated.
- Hooks/handlers, `beforeParse` and `afterHandle` are composed once, at registration, and stored on the route (`composed`, `composedPre`, `composedPost`); the `*Pre`/`*Post` slots stay `undefined` when empty so the request path skips them with one check. Per-request state (`handlerCalled`, `nextCalled`, the logger's clock) must stay outside the composed closure.
- Validation/parsing errors are reported as `RequestError` (HTTP-mapped); `validator.ts` throws plain strings internally, always wrap them in `RequestError` at boundaries (`parser.ts`, `server.ts` pattern). Handlers/hooks/middleware report errors by throwing `RequestError` subclasses (the `mkErr` classes in `src/types.ts`); anything else becomes a 500.
- Response maps are keyed by exact status, `'1XX'`–`'5XX'` range or `'default'`, and **one** resolution rule governs everything — `responseEntryFor`: exact status, then the containing range, then `default`. Response validation, the content type inferred for a string response, the emitted spec and the generated client all go through it; never re-implement the precedence locally.
- The SSE path uses a `ReadableStream({ type: 'direct' })`, frames multi-line values as one `data:` field per line, and derives ids from one `crypto.randomUUID()` prefix plus a counter per connection (not a CSPRNG call per event).
- `ctx.set.headers` always carries the `'set-cookie': []` sentinel and may hold array values. Cookies and `set.headers` are merged into a response with **append** semantics — building a `Headers` from the object would stringify them (`'a,b'`, `'set-cookie: ""'`).
- `trustProxy` is compiled once at boot (`clientAddressResolver`), so a misconfiguration throws at boot rather than per request. The forward chain is the socket peer followed by `X-Forwarded-For` right to left; the socket peer wins whenever the chain cannot be walked as configured, `MAX_FORWARDED_HOPS` (32) bounds the walk, and `ctx.clientAddress` is lazy — `ctx.remoteAddress` stays the raw socket peer.
- `galbe.static(path, target)` walks the target at registration and throws if it does not exist. In production it resolves the target as `static-<GALBE_BUILD>/<target>` next to the bundle, which is why `Galbe.staticTargets` is recorded and `galbe build` copies the assets there and emits `Bun.env.GALBE_BUILD`.
- The ARA assumes route registration is **synchronous** inside a file's default export: it correlates registrations to files through `galbe.onRouteAdded` (subscribing around each import). Middleware files are registered before route files, shallowest directory first, so outer scopes wrap in-file registrations. `node_modules` and `.git` are never scanned (`NEVER_SCANNED_DIRS`) unless a pattern names them explicitly. `@galbe-ignore` unregisters a route from the router; `@galbe-hide` keeps it served but out of the route table. Directory names must be valid literal route segments and invalid ones are boot errors.
- `metaAnalysis` cannot use `Bun.Transpiler` (it strips comments); it transforms with `@swc/wasm` first. The JSDoc head/tag split treats the first `@tag` line as the boundary precisely because descriptions may contain `@` (package scopes).
- `bin/res/client.runtime.ts` is inlined **verbatim** into generated clients: keep it dependency-free and export-free.
- Code style follows `.prettierrc`: no semicolons, single quotes, 2 spaces, print width 120, arrow parens avoided. Prettier is pinned and CI runs `bun run format:check`, so the tree must stay clean — run `bun run format` before finishing. `.prettierignore` exempts the generated `CHANGELOG.md`, `test/__snapshots__/`, and `test/resources/` (hand-authored fixtures, one of them deliberately malformed JSON). Use `// prettier-ignore` / `<!-- prettier-ignore -->` where reflowing would break meaning — notably around a `@ts-ignore`, which prettier can detach from the line it suppresses when it reflows.
- `Context<M, Path, S>` (`src/types.ts`) is built from three helpers: `ContextBody` derives the `contentType`/`body` pair per media type (that union is what makes `ctx.contentType` a discriminant), and `ContextOf` holds the single object literal for every other field. Keep the literal in exactly one place, and keep `ContextOf`'s top level a conditional over a naked `B` — a helper that resolves straight to an object type would make editors hover `ctx` as an alias reference instead of its expanded shape. `test/schemaTyping.test.ts` (`describe('context typing')`) is the guardrail; it is typecheck-only, so a regression shows up in `bun run typecheck`, not in `bun test`.
- Changes to router/parser/server behavior need tests in the matching `test/*.test.ts` file; a new middleware goes with `test/middlewares.*.test.ts` plus its spec expectations; run `bun test` and `bun run typecheck` before finishing.

## OpenAPI

`OpenAPISerializer` (`galbe/extras`) turns registered routes plus their schemas into an OpenAPI 3 document; `galbe generate spec` wraps it, `galbe generate code` goes the other way, and `galbe generate client` / `generate cli` consume the same route model.

- Security is **declared, never inferred**: an operation is documented as authenticated only where a scheme is named — a route's `@security`, its route file's header, or the `security` of a covered middleware def (nearest scope first: exact beats a same-length wildcard, a file's header ahead of the def it annotates). First non-`undefined` scope wins outright, with no merging; nothing declared anywhere means the operation documents as public, while `@security none` produces an explicit `security: []` — a real distinction. `@tags` accumulates across scopes (deduped), unlike `security`.
- `components.securitySchemes` merge order is `config.openapi.securitySchemes` > middleware defs in registration order (first def to claim a name wins) > the `bearerAuth` default. The def loop runs over **all** registered middleware, matching a route or not, so a scheme can be declared with no operation using it.
- The resolved scheme owns its credential: `http` schemes remove the `authorization` header parameter and `apiKey` schemes remove the parameter for their `in`/`name`. That is why the shipped middlewares' headers normally do not appear as plain parameters.
- Tags read off route/middleware meta: the JSDoc `head` (first paragraph = summary, after the first blank line = description, overridable half-by-half by `@summary`/`@description`), `@tags` (space-separated), `@tag` (repeatable), `@security`, `@externalDocs`, `@operationId`, `@deprecated`, `@hide`, plus the `static` meta key. `@response` is **not** a tag anywhere in this repo: responses come only from `r.schema.response`. `@galbe-ignore`, `@galbe-hide` and `@prefix` belong to the route analyzer (`src/routes.ts`), not the serializer.
- Schemas with an `id` are hoisted into `components.schemas` and `$ref`d (first write wins for a given id), and a parameter appearing on two or more operations is promoted into `components.parameters`. Only `draft4Bounds` (numeric vs boolean `exclusiveMinimum`/`exclusiveMaximum`) is version-conditional — `nullable: true` is emitted even for a `3.1` document.
- Coverage is snapshot-driven: `test/openapiExhaustive.test.ts` runs `generate code` then `generate spec` over `test/resources/openapi.exhaustive.yaml` (a construct-by-construct fixture) and pins both the generated sources and the structural diff against the source spec, while `test/openapiRoundtrip.test.ts` does the same over the realistically shaped `openapi.fixture.yaml`. Those diff snapshots _are_ the inventory of what the roundtrip loses — shrinking them is the goal, growing them is a regression, so read the delta rather than accepting it. Refresh with `bun test --update-snapshots test/openapiExhaustive.test.ts` **and** `bun test --update-snapshots test/openapiRoundtrip.test.ts` (they hold separate snapshot files). Constructs the code generator cannot express are printed rather than dropped silently.

## Known gaps

Verified by reading and running the code, but **not** covered by any test. Fix them with a test, not silently.

- `schemaToOpenapi` serializes a `pattern` with `toString().substring(1, len - 1)`, which is only correct for a flagless literal: `/^Bearer /i` (the fragment the auth middlewares ship) becomes `"^Bearer /"` — the flag is lost and the closing `/` leaks. Latent today because the resolved security scheme removes the parameter.
- A valueless `@tag` crashes the serializer (`parseComment` yields `true`, which is then spread). A bare `@security` does not crash but is silently ignored (documents as public, not `[]`), and repeated `@tags` lines are dropped while repeated `@tag` survives.
- Component registration tests `schema.id in components.schemas` on a plain object, so an `id` like `toString` registers nothing and emits a dangling `$ref` — the same prototype-collision class the rest of the codebase guards with `Object.hasOwn`.
- `galbe build` writes its `BUN_ENV`/`GALBE_BUILD` assignments _after_ the generated entry's imports, and ESM imports evaluate first: an app calling `static()` at module scope reads `GALBE_BUILD` as `undefined`, so running the bundle with `BUN_ENV=production` alone fails with `static-undefined/<target>`. It also exits 0 when `Bun.build` itself fails, and its temp entry dir is removed only on the happy path. `test/build.test.ts` covers boot and boot-error reporting only.
- `generate model` interpolates `--schema`/`--table` straight into its `information_schema` queries, ignores `-F/--force`, and tests `is_nullable` for truthiness although it is the string `'YES'`/`'NO'` — so every column is typed `| null`. There is no test file for it at all.
- `dev` reload failures only log and leave the server stopped until the next save, and the respawn strategy does not forward `-w`/`-wi`/`-nc` to the child.
- A bare `AuthError` escaping `authHook` (thrown by a user hook, say) is a 500, since it is not a `RequestError`.
- `checkRealm`-style validation is not applied everywhere a value becomes a header: `securityMetadata`'s `rename` accepts `''`, producing a scheme named the empty string.
